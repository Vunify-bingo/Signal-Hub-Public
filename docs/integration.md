## 两种不同的对接方向

### 业务系统调用 Signal Hub

已有后端接口覆盖企微账号、客户与标签、消息查询和发送、素材、群发计划、逐条结果及管理操作。具体接口清单、字段与权限以交付版本为准。

当前受保护业务接口使用登录会话和角色授权，服务端限定租户数据范围。没有将“通用第三方 API Key”“OAuth 开放平台”“开箱即用 SSO”作为现成能力提供。生产系统集成时，需要确认服务身份、授权范围、审计及凭证生命周期，不能简单复用管理员浏览器会话作为长期方案。

适合讨论的集成场景包括：从 CRM 同步运营名单、按业务事件准备触达任务、查询任务结果、接入已有内容系统。这些是对接方向，不代表每一种第三方产品都有现成连接器。

### Signal Hub 调用租户知识库

这一方向已有标准协议：租户配置公网 HTTPS 接口与独立密钥，平台发送问题，知识库返回 reply / ignore / handoff。详见 [自动回复接口](auto-reply.md)。

## 消息通道

当前通过企微接入服务的同步与回调机制取得消息、联系人及账号状态。回调有独立鉴权，业务数据按账号归属确定租户。这里的“接收企微服务回调”不等于“向所有第三方业务系统提供通用 webhook 订阅”。

账号接入方式、可用消息类型、媒体及群相关能力需核对具体服务商能力。不将接入服务接口与企业微信官方接口混为一谈，也不承诺绕过平台限制。

## 建议的联调流程

1. 确认使用场景、账号数量、租户边界和权限。
2. 约定接口字段、目标标识、超时、错误与幂等规则。
3. 使用测试账号与脱敏问题验证数据流。
4. 先试运行，再限定测试联系人验证发送。
5. 验证接管、失败、断线及重复回调后，再扩大范围。

接入说明不是匿名公共服务入口，本仓库不包含可直接访问的生产地址或访问密钥。
